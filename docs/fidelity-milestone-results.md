## What changed

Existing CLI defaults, public `schema`/`schema/canonical` layouts, custom dialect
interfaces, and legacy SQL remain compatible. New behavior requires the explicit
`checked` or `strict` fidelity profile, or the separate public
`NewFidelityRenderer` constructor. The first supported opt-in pair is SQL Server
to PostgreSQL. See [CLI profiles](cli.md#opt-in-fidelity-profiles) and the
[public API contract](public-fidelity-api.md).

The deterministic renderer adds tinyint range and bounded varbinary byte-length
checks, preserving valid boundaries, NULLs and updates. A typed expression parser
also translates literal binary defaults, including empty and odd-length source
hex literals. Unsupported binary expressions refuse instead of emitting invalid
target SQL. Existing default rendering is unchanged in legacy mode.

The shared assessment reports unresolved precision, original-offset, date/time,
fixed-binary, Unicode, comparison, conversion, identity and unassessed-type
semantics. Nullable unique keys are explicitly flagged after the live suite
confirmed different NULL uniqueness behavior. Strict rejects unresolved
findings; it is not a proof of universal equivalence. The public API assesses
only supplied metadata, with separate optional unique-index and constraint-name
context that does not render side objects.

Checked create/apply refuses existing tables before executing its plan. Live
drift/sync recognizes generated checks by expected name, supported predicate and
validated catalog status. Exact binary defaults compare by parsed bytes. New
tables and verified no-ops are supported; existing-table evolution, profile
transitions and snapshot-based opt-in sync explicitly refuse before returning a
partial plan. Optional manifests carry profile, semantics version, requirements
and findings; opt-in input and plan hashes distinguish policies. Renderer version
21 records the new capability. AI did not author any executable migration SQL.

## Remaining limits and release gates

The 19 source-backed differences are fixed-binary padding/overflow (2), time
input and rounding (12), legacy datetime/smalldatetime behavior (3), UTF-16
overflow (1), and nullable uniqueness (1). Native conversions and application
interfaces need further work; a stored-byte CHECK does not reproduce all
source-side casts. Optional AI semantic review has not been extended in this
milestone. It remains a later diagnostic layer over deterministic SQL.

Checked/strict do not support altering existing schemas yet. Source check
expression semantics and cross-table side-object naming remain subject to the
existing renderer's limitations. Strict's assessed scope must not be advertised
as full schema behavioral equivalence.

Live source evidence uses the pinned retired Azure SQL Edge ARM64 build
15.0.2000.1574 and PostgreSQL 17.11. Before a release claim, run the supported
SQL Server acceptance gate and the full nine-pair CRM matrix. Race-detector and
golangci-lint gates remain outstanding because the WSL environment lacks a C
compiler and golangci-lint. No new live AI request was needed. The user authorized
a local branch commit after validation. No push, merge, release, or deployment
was performed.
